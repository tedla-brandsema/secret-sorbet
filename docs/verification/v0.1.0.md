# v0.1.0 release verification

This is a point-in-time record for the initial development source release.
The [release plan](../plans/v0.1.0-release.md) defines acceptance;
[machine-readable evidence](v0.1.0.json) retains identities and outcomes.
This engineering review is not an independent external security audit.

## Local verification

On 2026-10-17, the Rust 1.98.0 baseline passed formatting, Clippy with warnings
denied, all 68 workspace tests in each of debug and release, the release CLI
build, and rustdoc with warnings denied. Both lockfile audits passed against
1,334 RustSec advisories (180 workspace dependencies and 41 fuzz dependencies).
All 13 evidence-harness regressions and independent Python/libargon2 fixture
reproduction passed. The bounded policy fuzz smoke test completed 10,000 runs
with seed 50100 and maximum input length 64. Its package graph stayed unchanged.

An isolated local clone tagged `v0.1.0` passed Cargo's Git-source installation
with the pinned toolchain into a temporary installation root. The installed
binary reported `seso 0.1.0`, and help output succeeded. This test did not create
the real repository's release tag or generate a credential. Version consistency,
local Markdown links/anchors, unchanged historical matrix contents, and diff
checks passed. Commands and details are retained in the JSON record.

## Inspected CI evidence

[Run 39023700177](https://github.com/tedla-brandsema/secret-sorbet/actions/runs/39023700177)
passed all 12 jobs at `d21b4db787e68df2b18d7fc75c7f315a310c5ed0`.
All nine native/emulated execution artifacts were downloaded with authenticated
GitHub access and their payloads inspected. Each reports the expected target,
compiler, runtime architecture/OS/word size/endianness, tested commit, and two
successful debug/release commands. The six native jobs run workspace tests;
the three QEMU jobs run only core/password suites.

Every lockfile and fixture hash matches the source checkout, accounting for
Windows Git checkouts converting LF to CRLF. The JSON retains both raw artifact
hashes and local LF hashes, and verifies that each differing hash equals exactly
the LF-to-CRLF transformation. This is file checkout handling; passphrase bytes
and fixture input strings are not normalized. A second agent independently
checked all nine payloads and job outcomes with no discrepancies.

Runtime, build, CI and fixture files are unchanged by release preparation. The
JSON records their hashes to distinguish these checks from later documentation
commits. R03 additionally requires passing CI on the exact release candidate
before tagging. Publication and final candidate evidence are recorded after
those operations succeed; this baseline alone is not publication evidence.

## Review and remaining scope

An independent adversarial source/documentation review found no material
release blocker in deterministic contracts, input validation, error/redaction
paths, package boundaries, or CLI secret-output handling. The separate evidence
and intended release-note review also passed with no material corrections.
Exact-candidate CI and remote publication verification remain R03 gates.
CI clipboard tests
use mocks; they do not demonstrate actual OS history-manager or interactive
terminal behavior. Platform clipboard limits remain documented in the
[CLI guide](../../app/cli/README.md).

P06 normalization and P07 mobile execution remain deferred. The broader P08
portability gate is open. Desktop/mobile/browser applications beyond the CLI
remain planned. The [support contract](../support.md) defines runtime limits,
exact v1 input bytes and safe recovery requirements.
