# v0.1.0 source release

The user authorized preparation and publication of GitHub release `v0.1.0` on
2026-10-17. This is the initial development source release of the Rust libraries
and `seso` CLI. Existing crate versions are already `0.1.0`. It includes GitHub's
source archives; publishing crates to a registry or supplying prebuilt binaries
is outside this delivery. No derivation or compatibility profile change is planned.

The [roadmap](../ROADMAP.md) owns progress and its checkbox legend. The
[TODO](../TODO.md) retains deferred work. This release has a separate scoped gate:
P06/P07 remain deferred and the broader P08 portability gate remains open.
Release authorization does not supply missing mobile execution or approve NFC.

files. Review corrections return to their owner; runtime fixes require focused
tests and their own reviewed commit before release.

## Acceptance and verification

- Check clean Git state, exact origin/main, authenticated account, remote tag and
  release absence. Never replace an existing tag or published release.
- Confirm all three workspace package versions and the CLI version are `0.1.0`.
- Run formatting, Clippy with warnings denied, serialized debug/release workspace
  tests, release CLI build, rustdoc with warnings denied, both dependency audits,
  harness regressions, independent fixture reproduction, and bounded policy fuzz.
- Validate source installation from an isolated local Git clone; smoke-test only
  help/version output, without generating or printing credentials.
- Verify all six native and three QEMU debug/release jobs and their actual
  execution-step outcomes. Inspect downloaded artifact payloads against their
  tested commit, lockfile/fixture hashes, compiler and runtime identity.
- Before tagging, require the exact candidate's complete Rust workflow to pass.
  Record durable evidence, distinguish the snapshot's tested revision from later
  documentation commits, and preserve historical evidence as a point-in-time record.
- Independently review source, safe diagnostics, release notes, links, limitations
  and version consistency. Record material findings and closure in verification.
- Keep an empty `Unreleased` section; date the authorized `0.1.0` changelog entry
  for actual publication. If publication slips to another date, correct it first.
- Prepare the release body from the reviewed changelog plus source installation
  and limitations. Use a notes file, an existing verified tag, and a draft before
  publishing. Verify tag object/commit, release body/status, URL and archive links.

## Required release limits

This development release has no independent external security audit or mobile
execution evidence. Native tests cover six named desktop targets; three GNU
Linux targets run shared-library tests under QEMU. These tests do not establish
every OS distribution, device, clipboard manager, or future application. v1 uses
exact UTF-8 passphrase bytes with no Unicode normalization and needs `std`, heap
allocation, thread support and Argon2's 64 MiB working memory plus overhead.
Preserve original recovery inputs and the profile/policy; do not silently
normalize inputs or claim an automatic migration. The apps beyond CLI are planned.
